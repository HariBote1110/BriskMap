# 本番の表示画面のスマホ相当環境での計測（M5 の完了条件）

2026-09-30。環境と手順は [phone-equivalent.md](../feasibility_research/notes/phone-equivalent.md) と同じ（LXC 118、Ryzen 3 4300U の 4 コアを cpulimit 1.6、内蔵 GPU、Chromium 154 ヘッドレス、モバイル表示、半径 256 ブロック＝864 チャンク）。地図は同じ基準ワールド（1.21.11、484 リージョン）を、プラグインを入れた Paper（`/opt/dev/pbench`、ポート 8124）から配信。計測道具は `feasibility_research/tools/clientbench` の `--brisk-prod-url`。

## Decision

- 完了条件「読み込み 3 秒以内・30 fps 以上」を満たした（2.2〜2.3 秒・60 fps）。
- チャンクの展開はブラウザの `DecompressionStream` ではなく、WASM に入れた自前の raw DEFLATE 展開器で行う。

## 結果（視点 3 つ × 各 3 回の中央値、全回有効）

| | 読み込み完了 | 読み込み中の CPU | 回転中の fps | 回転中の CPU |
|---|---|---|---|---|
| BlueMap 5.16 | 8.0〜11.8 秒 | 12.6〜18.0 秒 | 38〜60 | 10.5〜16.0 秒 |
| 検証用の画面 | 2.3〜2.4 秒 | 4.5〜4.6 秒 | 60 | 4.4〜4.8 秒 |
| 本番（最初の版） | 3.3〜3.5 秒 | 5.3〜5.7 秒 | 60 | 6.0〜6.5 秒 |
| 本番（ワーカー先行起動・描画の間引き後） | 3.1〜3.2 秒 | 5.0〜5.2 秒 | 60 | 6.0〜6.5 秒 |
| **本番（WASM で展開）** | **2.2〜2.3 秒** | **3.6〜3.7 秒** | 60 | 5.9〜6.3 秒 |

内訳（本番・最終、代表 1 回）: 索引取得 0.49 秒 → 表示器の生成 0.82 秒 → 最初のデータ 1.01 秒 → 取得完了 1.50 秒 → 組み立て・GPU 転送完了 2.29 秒。ワーカー内の合計は展開 75 ms（以前は 3,871 ms）、組み立て 573 ms。

## Alternatives considered

- ワーカー数を増やす・先に起動する・描画を間引く: 効果は 0.3 秒どまりだった。時間の大半は展開だった（計測項目を足して初めて分かった）。
- `DecompressionStream` をまとめて呼ぶ: チャンクごとに別の圧縮ストリームなので、呼び出し回数は減らせない。

## Constraints / Gotchas

- `DecompressionStream` は 1 回あたり約 4.5 ms（この環境）の固定費がある。小さいデータを何百回も展開する用途には向かない。
- 回転中の CPU が検証用の画面より 3 割ほど多い（大半は GPU プロセス）。UI の半透明パネル（背景ぼかし）の合成が疑わしいが未確認。fps は 60 を保っている。
- 最初のデータまで 1.0 秒かかっている（検証用は 0.4 秒）。モジュールの読み込みと索引の取得が直列なため。次に縮めるならここ。
