# 地図データ形式（v6）

サーバーが書き出し、ブラウザが HTTP の Range 要求で読む、リージョン単位（32×32 チャンク）のファイルの仕様。実装は `core/.../format/Format.java`（書き込み）と `Reader.java`（読み込み）。

## ファイル

| 名前 | 中身 |
|---|---|
| `r.X.Z.b2d` | 2D 地図用。各列（x, z）の最上面のブロック・バイオーム・水深 |
| `r.X.Z.b3d` | 3D 表示用。外から見えるブロック（外殻）と、見える面の印 |

## 全体の並び

整数はすべて**ビッグエンディアン**。`varint` は 7 ビットずつ下位から並べ、続きがあるバイトは最上位ビットを 1 にする符号なし整数。

| 位置 | 大きさ | 内容 |
|---|---|---|
| 0 | 4 | `BRSK`（ASCII） |
| 4 | 1 | 形式の版 = `6` |
| 5 | 1 | 種類: `1` = 2D、`2` = 3D |
| 6 | 4 | リージョン X（符号付き） |
| 10 | 4 | リージョン Z（符号付き） |
| 14 | 1 | 抽出設定: bit0 = 洞窟を隠す（caves hide）、bit1 = 液体は表面のみ（fluids surface）、bit2 = 26.3 形式の「名前だけ」の状態をサーバーの既定状態表で全属性つきに補った。他のビットは 0。差分更新ではこのバイト全体を比べ、違えば全体抽出し直す |
| 15 | 1 | `caveDepth`（0〜16）。0 は旧来の床より下を隠す判定。差分更新では値が変わると全体を再抽出する |
| 16 | 2 | `maxY`（i16。32767 は高さの切断なし。`worldY > maxY` を空気として抽出） |
| 18 | 可変 | ブロック状態の表: `varint 件数`、続いて各項目 `varint バイト数` ＋ UTF-8 文字列（例 `minecraft:oak_log[axis=y]`。属性は `k=v` の文字列順） |
| — | 可変 | 2D のみ: バイオームの表（同じ書き方） |
| — | 8192 | チャンク索引: 1024 件の（u32 ファイル先頭からの位置, u32 長さ）。チャンクの番号は `x + z*32`（リージョン内の座標）。無いチャンクは (0, 0) |
| — | 可変 | 各チャンクの本体。raw deflate（zlib ヘッダーなし）で圧縮 |
| 末尾−4628 | 4096 | 1024 件の u32: そのチャンクを抽出したときの .mca 上の保存時刻（秒）。.mca に存在しないチャンクは 0（未完成・未対応のチャンクも時刻を記録するので、変化がなければ再抽出しない） |
| 末尾−532 | 528 | 隣接リージョンの接辺 128 チャンクと斜め４リージョンの角４チャンクの保存時刻（u32）。接辺の順序は西側 z=0〜31、東側 z=0〜31、北側 x=0〜31、南側 x=0〜31。角の順序は北西、北東、南西、南東。隣接リージョンまたはチャンクが無い場合は 0 |
| 末尾−4 | 4 | `BRST`（ASCII） |

- ブラウザは「先頭から索引の終わりまで」を 1 回の Range 要求で読み、次に必要なチャンクの本体をまとめて読む。末尾の時刻表はサーバーの差分更新専用で、ブラウザは読まない（先頭の要求が大きくならないよう末尾に置いた）。
- ブロック状態の表は 2D と 3D で同じ内容を共有するのが普通だが、それぞれのファイルに完結して入っている。
- 差分更新では表は**追記のみ**（既存の番号は変えない）。使われなくなった項目も残る。

## チャンク本体（展開後）

### 2D（256 列、`x + z*16` の順）

各列: `i16 y`（最上面の高さ。何も無い列は −32768）、`varint ブロック番号`、`varint バイオーム番号`、`u8 水深`（水のとき水面から海底までのブロック数、上限 255。水以外は 0）。

### 3D（24 セクション、Y −64〜319 を 16 段ずつ、下から）

各セクション:

1. `varint 件数 n`
2. n 個の `varint 位置の差分`（セクション内の位置 `x + z*16 + y*256` を昇順に並べ、前との差。最初は 0 からの差）
3. n 個の `varint ブロック番号`
4. n 個の `u8 見える面の印`: bit0 −X（西）、bit1 +X（東）、bit2 −Y（下）、bit3 +Y（上）、bit4 −Z（北）、bit5 +Z（南）。0 と bit6・7 は使わない

## 抽出の決まり（見た目に効くもの）

- 抽出するのは `Status` が `minecraft:full` のチャンクだけ。
- リージョンの境目では四辺と四隅の接するチャンクを読み、リージョン内と同じ到達判定を適用する。隣接リージョンまたはチャンクが無い・未完成なら空いているとみなす。
- リージョン内でチャンクが無い・未完成の場所も空いているとみなす。チャンクの保存時刻が変わると、その周囲３×３チャンクを再抽出する。隣接リージョンの時刻変化は接辺から１チャンク以内を再抽出する。
- 洞窟を隠す設定（既定）: 遮蔽しないセルのうち、床以上のセルを外とみなす。床より下でも外から６方向に `caveDepth` ステップ以内でたどれるセルに面を出す。床は通常 `OCEAN_FLOOR`、高さの切断時は `maxY` 以下で最も高い遮蔽ブロックの１段上を使う。従来の高さ 55 以上を表示する規則も維持する。
- 高さを切断した場合、2D の最上面も切断以下の非空気ブロックから探す。切断面にあるブロックの上面は見える。
- 液体は表面のみ（既定）: 同じ液体どうしの間の面は出さない。

## 版の方針

- v6 は v5 の予約バイトに `caveDepth` を格納し、時刻表に斜め４リージョンの角を追加したもの。表とチャンク本体の符号化は同じ。
- 版の番号が変わったら、サーバーは古いファイルを差分更新に使わず全体抽出し直す。
- ブラウザは知らない版のファイルを読まない（エラーを表示する）。
- 検証時の v1（2D）・v2（3D）とは、先頭 18 バイトと末尾の時刻表以外は同じ並び。
