# 要件（草案）

実現性検証の結果次第で大きく変わるため、現時点では決定事項と未決事項の整理のみ。

## 決定事項

- 対象サーバー: Paper
- 表示: 2D（真上）と 3D の両方
- 持ち出しやすさ: ファイルコピーが効率的な形式（少ないファイル数、小さい容量、差分コピーが効く）
- 言語・対応版・ライセンス・MVP の範囲: [ADR 0002](Decisions/0002-foundation.md)（Java、1.21.11〜26.3、MIT）
- 3D の形はブラウザで組み立てる（検証で BlueMap より軽いことを確認。[ADR 0001](Decisions/0001-go-no-go.md)）

## 未決事項

### 性能目標（ブラウザ側描画の可否を決めるのに必須）

- [ ] 基準とする端末（ノート PC・スマホの具体的な機種）
  - 方針（2026-09-29）: 手元の端末はハイエンドばかりで基準にならないため、**Proxmox 上に低性能スマホ相当の VM を作って確かめる**。CPU コア数・クロック上限・メモリ・GPU なし（ソフトウェア描画）などで性能を絞る。どの実機に相当させるかは未決定
- [ ] 目標 fps（例: PC 60fps、スマホ 30fps）
- [ ] 初回表示までの時間（例: 2 秒以内）
- [ ] タブのメモリ上限（特に iOS Safari）

### 描画

- [ ] 3D の形をブラウザで組み立てるか、サーバーで作るか（実測で決める）
- [ ] 2D に等角図（Dynmap 風）を含めるか
- [ ] 昼夜・洞窟・ネザーの表示
- [ ] 立方体でないブロック（階段・柵・ガラス板など）の扱い
- [ ] 性能が足りない端末向けの代わりの手段（縮小表示だけサーバーで画像化する、など）

### 保存形式

- [ ] 圧縮方式（zstd＋辞書 / ブラウザ標準の gzip・deflate）
- [ ] 形式の版番号と移行方針
- [ ] 書き込み中のコピーでも壊れない方式（一時ファイル＋名前の差し替え）
- [ ] 持ち運び用に 1 ファイルへまとめる `pack` コマンド

### 更新

- [ ] 初回はディスク上の .mca から、以降は Paper のイベントで追いかける 2 段構え
- [ ] メモリ上の最新状態とディスクのずれの扱い

### 対応する版

- [ ] 対応する Minecraft / Paper の版の範囲（最新のみか、過去版も追うか）

### 機能（MVP / v1 / 将来 に振り分ける）

- [ ] リアルタイム更新（WebSocket / SSE）: プレイヤー位置、チャット
- [ ] マーカー API（Dynmap の Marker API と互換にするか）
- [ ] Dynmap / BlueMap からの移行ツール
- [ ] REST API（OpenAPI）
- [ ] 静的書き出し
- [ ] 過去の地図の表示（差分保存）
- [ ] PWA、スマホ対応、ダークモード、URL での位置共有、検索
- [ ] Web 画面の認証・権限

### 横断的事項

- [ ] テクスチャの入手方法（クライアント jar を同意を得てダウンロード / リソースパック指定）
- [ ] プライバシー（透明化・vanish 中のプレイヤー、非表示範囲）
- [ ] ライセンス
- [ ] 組み込み Web サーバーのセキュリティ（リクエスト数制限、リバースプロキシ前提か）
- [ ] テスト方針（Minecraft 非依存の中核モジュールを切り出す）
