# 開発計画（MVP）

範囲は [ADR 0002](Decisions/0002-foundation.md)。各段階は TDD（テスト → 実装 → 整理）で進め、段階ごとに完了条件を満たしてから次へ進む。

## 構成

```
BriskMap/
├── core/     Minecraft・Paper に依存しない中核（NBT・.mca 読み取り・地表抽出・保存形式・テクスチャ生成）
├── paper/    Paper プラグイン（起動・設定・スケジューラ・イベント追従・Web サーバー）
├── web/      ブラウザ側（表示画面、Rust→WASM の組み立て処理）
└── feasibility_research/  検証時の道具と記録（本体からは参照しない）
```

## 段階

| # | 段階 | 内容 | 完了条件 |
|---|---|---|---|
| M0 | 土台 | Gradle（Wrapper 同梱）の複数モジュール構成、JUnit 5、空のプラグインが Paper に読み込まれる | `./gradlew build` が通り、Paper 1.21.11 と 26.3 で有効化のログが出る |
| M1 | 中核の抽出 | 検証用抽出器を `core` へ移植（NBT、.mca、地表 2D、外殻 3D v2、原子的な書き込み）。リージョンごとの「どのチャンクをいつ抽出したか」の記録 | 検証用抽出器と同じ入力で**同一のバイト列**を出す試験が通る |
| M2 | テクスチャ | 検証用テクスチャ道具を Java へ移植。同意設定つきのクライアント jar 取得、アトラス・材質表の生成、材質表の軽量化 | 同じ jar から検証用道具と同一のアトラス、同等の材質表ができる |
| M3 | プラグインの抽出処理 | 起動時の全体抽出（非同期・スレッド数上限つき）、変更チャンクの追従、`/briskmap` コマンド（状態表示・再抽出） | 実サーバーでブロックを置くと、保存後に該当リージョンが更新される |
| M4 | Web サーバー | JDK 内蔵の HTTP サーバーで地図データ・テクスチャ・画面を配信（Range・gzip・キャッシュ制御） | 検証用 `serve.mjs` と同じ試験項目が通る |
| M5 | 表示画面 | 3D 近景（検証用 viewer の本番化）と 2D 地図、視点の URL 共有、スマホ操作 | スマホ相当環境で読み込み 3 秒以内・30 fps 以上 |

## 各段階で文書化すること

- M1: 保存形式の仕様書（`.b2d`・`.b3d` の版番号と互換性の方針）
- M2: テクスチャ入手の同意の流れ（EULA）
- M3: 設定項目の一覧、スレッド数と TPS への影響
- M4: 公開時の注意（リバースプロキシ前提か、リクエスト数制限）
