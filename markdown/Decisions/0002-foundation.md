# ADR 0002: 開発の土台（言語・対応版・ライセンス・MVP の範囲）

- 状態: 採択
- 日付: 2026-09-30

## 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| サーバー側の言語 | **Java**（`--release 21` でビルド） | Paper の標準。検証で作った抽出器（Java 21・依存なし）を流用できる。Kotlin 本体の同梱が要らず jar が小さい |
| ブラウザ側 | JavaScript（依存なし）＋ 形の組み立ては **Rust→WASM** | 検証で JS より 3 倍以上速く、JS 版と出力が同一であることを確認済み |
| ビルド | Gradle（Wrapper を同梱）。`core`（Minecraft・Paper に依存しない中核）と `paper`（プラグイン）と `web`（ブラウザ側）に分ける | 中核を Paper なしで試験できるようにする |
| 対応版 | **Minecraft 1.21.11 〜 26.3**（Paper） | 「直近の数版」。1.21.11 は検証の基準ワールドの版。26.x は Java 25 必須だが、Java 21 向けのバイトコードはそのまま動く |
| Paper API | 対応範囲の最も古い版（1.21.11）の API に対してビルドし、それ以降で削除・変更された API は使わない | 1 つの jar で全対応版を動かす |
| ライセンス | **MIT** | 制約が少ない。BlueMap と同じ |

## MVP の範囲

含める:

1. 起動時の全体抽出（.mca → リージョン単位の `.b2d`・`.b3d`）
2. ブロック変更への追従（変更のあったチャンクだけ抽出し直す）
3. 組み込み Web サーバー（Range 要求・gzip 対応）
4. ブラウザの 3D 近景表示（テクスチャ・AO 付き）と 2D 地図
5. テクスチャの用意（利用者の同意を得てクライアント jar をダウンロードし、サーバー上でアトラスと材質表を作る）

含めない（次の段階）: プレイヤー位置などのリアルタイム表示、マーカー、遠景（2D の縮小段）、Dynmap / BlueMap からの移行、認証。

## 版の違いの扱い

- ワールドの保存形式（.mca・チャンクの NBT）は 1.18 以降ほぼ同じで、ブロックは状態名の文字列で保存される。版の差は主に「新しいブロック名が増える」「テクスチャ・モデルが変わる」に表れる。
- テクスチャと材質表は**サーバーの版に合ったクライアント jar から作る**ので、版ごとの対応表を手で持たない。
- チャンクの DataVersion を記録し、対応範囲外なら警告する。

## 検討して見送ったもの

- Kotlin: Kotlin 本体（数 MB）の同梱か Paper の読み込み機能が必要になる。
- 抽出処理を Rust（JNI）で書く: OS と CPU の組み合わせごとにビルドが必要で、配布と保守が重い。検証では Java でも BlueMap の 24 倍速かった。
- 最新版のみ対応: 1.21.11 のサーバーがまだ多いと考え、直近の数版とした。
