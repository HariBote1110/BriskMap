# ブラウザ側の負荷: BriskMap と BlueMap の比較

## 目的 / 仮説

BriskMap はサーバーで描画しない分、3D の形の組み立てをブラウザで行う。利用者の端末にかかる負荷が BlueMap と比べてどうなるかを、同じカメラ・同じ表示範囲で比べる。

Dynmap は描画済み画像を並べるだけなので、ブラウザ側の計算負荷は小さいと見込み、今回は対象外とする（通信量・リクエスト数は多い）。

- **H6（転送量）:** 近距離 3D の範囲を揃えた条件（半径 256 ブロック）で、BriskMap の転送量は BlueMap の **1/3 以下**。
  - 根拠: BlueMap は斜め視点（距離 120）で近距離 3D だけで 238 件・11.2 MB を読み込んだ。BriskMap の 3D データ（hide/surface）は 1 リージョン平均約 0.75 MB で、半径 256 ブロック（約 804 チャンク）なら 1 MB 未満の見込み。
  - 棄却条件: 1/3 を超える。
- **H7（CPU 時間）:** 読み込み完了までのブラウザ全体の CPU 時間は、BlueMap の **2 倍以内**（BriskMap は組み立てを行う分、増える前提）。
  - 棄却条件: 2 倍を超える。
- **H8（GPU メモリ）:** GPU に送るデータ量は BlueMap 以下。BlueMap の頂点は UV・法線・色・AO などの属性を持つため、1 頂点 12 バイトの BriskMap のほうが小さいと予想する。
  - 棄却条件: BlueMap を上回る。
- **H9（fps）:** カメラを 10 秒で 1 周させたときの平均 fps は、両者とも 55 以上（Apple M4、1600×900、倍率 1）。

## 比較の条件（公平性）

- 案 A: 近距離 3D の範囲を両者とも半径 256 ブロックに揃え、BlueMap の遠景（lowres）は 0 にする。
- 案 B: BlueMap は既定設定（近距離 100、遠景 2,000）。利用者が実際に受ける負荷の参考値。BriskMap は案 A と同じもので比べない。
- BriskMap は色のみ（テクスチャ・光・影なし）、階段なども立方体。BlueMap はテクスチャ・光・AO あり。**BriskMap に有利な差であることを結論に明記する。**
- BriskMap のデータは `--caves hide --fluids surface`（BlueMap の既定 `remove-caves-below-y: 55`、水面のみの描画に近い）。
- 配信は両方とも検証用コンテナ（192.168.0.175）から LAN 越し。BlueMap は組み込み Web サーバー（ポート 8100、gzip）、BriskMap は Range 対応の静的サーバー（ポート 8200）。

## 環境

- ブラウザ: Mac mini（Apple M4、10 コア、32GB）上の Google Chrome for Testing（Playwright chromium-1223、GPU あり、画面表示あり）。実行ごとに新しいプロファイル、キャッシュ無効、ウィンドウ 1600×900、`--force-device-scale-factor=1`
- 測定: `tools/clientbench/`（CDP で操作）
